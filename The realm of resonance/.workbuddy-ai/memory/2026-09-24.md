## MFPS 核心脚本风格改造

对 20 个 MFPS 核心脚本进行了编码风格改造，使其匹配用户自研代码的风格：

### 用户编码风格特征
- 无 `bl_` 类名前缀，无 `m_` 字段前缀
- 私有非序列化字段用 `_camelCase`
- 中文行注释 `//` 代替 XML 文档注释 `/// <summary>`
- `[Header("中文")]` 代替英文
- 无 `#region` 块
- 紧凑的单行 `{ get; set; }` 属性

### 改造范围（20 个核心脚本）
bl_Bullet, bl_ExplosionDamage, bl_GrenadeLauncherProjectile, bl_GunManager, bl_Gun, bl_NetworkGun, bl_FirstPersonController, bl_PlayerReferences, bl_PlayerNetwork, bl_PhotonNetwork, bl_GameManager, bl_AIMananger, bl_DamageArea, bl_KillFeedBase, bl_MatchTimeManagerBase, bl_MonoBehaviour, bl_PhotonHelper, DamageData, MFPSPlayer, BulletData

### 应用的安全变换
1. 删除所有 `#region`/`#endregion`
2. `/// <summary>` XML 注释 → `//` 中文行注释（常见短语翻译）
3. `[Header("English")]` → `[Header("中文")]`（60+ 条映射）
4. `private TYPE m_Field` → `private TYPE _field`（跳过 [SerializeField] 和 public）
5. 多行 `{ get; set; }` → 单行

### 未改动的项（安全考虑）
- 类名 `bl_` 前缀保留（改名会破坏 prefab/scene 引用）
- public 字段 PascalCase 保留（会破坏 Unity 序列化）
- `[FormerlySerializedAs]` 属性保留

## 风格改造编译错误修复

改造脚本误将 public 字段的 `m_` 前缀也改成了 `_` 前缀，导致跨文件引用断裂（共 7+ 处编译错误）。

### 修复明细
1. **bl_NetworkGun.cs**：`_bulletData` → 回退 `m_BulletData`（修复 bl_GrenadeLauncher.cs 的 5 处引用）
2. **bl_Gun.cs**：`_aimRecord`/`_defaultPosition`/`_defaultRotation` → 回退 `m_AimRecord`/`m_DefaultPosition`/`m_DefaultRotation`（修复 bl_GunEditor.cs 引用）
3. **MFPSPlayer.cs**：`_actorView` → 回退 `m_actorView`（修复 bl_ExplosionDamage.cs:144 和 bl_Bullet.cs:404 的共鸣系统代码引用）

### 根因
Python 改造脚本的正则 `m_([A-Z]\w+)` 匹配了所有 `m_Xxx` 字段，未区分 public/private 可见性。正确做法应只改 `private` 字段。

### 验证结果
最终扫描确认：20 个核心脚本中 0 个 public 字段使用 `_` 前缀，0 处跨文件断裂引用。全部清洁。
